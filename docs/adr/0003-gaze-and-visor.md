# ADR 0003 — 視線はフレームが持ち、HUD は 3 行の計器にする

- 状態: 受理
- 日付: 2026-10-24
- Issue: #27
- 影響する規則: ARC-001 / ARC-007 / SWF-012

## 文脈

疑似 3D の目はマスの中心にある。正面の壁までの距離と左右の壁までの距離が同じで、視野の平面は 0.7 なので、突き当たりではすべての視線が正面の壁に先に当たる。一歩は `FloorReducer.tick` の 1 回で、その途中の絵は無い。HUD は 2 行で、`FrameLook` は色と図法と向きだけを持つ。

施主は、一歩の途中を描くこと、正面が壁でも左右の壁を描くこと、マトリックスや攻殻機動隊のような計器で情報を出すことを求めた。

## 決定

1 フレームの視線は `Gaze`（向き、論理座標、前進の割合）として `FrameLook` が持つ。前進の割合 0 は静止、1 は次のマスの静止位置である。静止時の目はマス中心より 0.46 後ろで、この定数は Render の `DepthEye` だけが持つ。HUD は `HudLayout` の 3 行で、枠は ASCII の `/` `\` `|` `=` `[` `]` とする。

## 強制

公開の初期化子が視線を一つ受け、描画と実行ファイルの両方がそれを渡す。中間の枚数と待ちは実行ファイルだけが持ち、Render は時計を読まない。`FloorReducer.tick` と `StepPace` は変えない。機械のゲートは、突き当たりの端の列が左右の壁であることと、前進で正面が近づくことと、HUD がシードを切らないことをテストする。

## 結果

突き当たりで左右の壁が見え、一歩が数枚に分かれる。視野の平面 0.7 は維持するので、左右に出る幅はマスの中に収まる範囲に限られる。3 行を HUD に使うので、迷路に使える行は 1 行減る。`along` を渡さない呼び出しはコンパイルできない。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| 視野の平面 0.7 を広げる | 廊下の見え方まで変わる。目を後ろにずらせば、マスの中にいたまま左右が入る |
| 目を壁の中まで進める | 距離が潰れて面が画面を埋める |
| `FloorReducer` に半歩を足す | 移動の正典が二つになる |
| 中間の待ちを `StepPace` に書く | 2D の一歩まで遅くなる。3D の表示時間は実行ファイルの sleep だけ |
| 静止の 167ms を 200ms や 500ms にする | 施主の前の決定を、この依頼は覆していない |
| HUD を 2 行のまま隙間を広げる | 情報の面にならない |
| Unicode の罫線、全幅の chip、実在しない語句 | 幅が曖昧になる。地を塗る HUD と、値のないラベルは既に退けた |
| 座標を `HudClock` に載せる | 時計の写しに位置を混ぜる |
| `paint` に第 5 引数を足す | 引数は 4 つまで |
