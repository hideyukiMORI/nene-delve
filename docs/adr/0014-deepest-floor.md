# ADR 0014 — HUD に起動以来の最深階を出す

- 状態: 受理
- 日付: 2026-10-25
- Issue: #51
- 影響する規則: ARC-001 / ARC-007 / ARC-011 / ARC-012

## 文脈

HUD はいまの階を `B3F` と出す。上に戻ると数字は小さくなる。起動してから着いた最も深い階は残らない。

`Delver.risen` は、同じ階を二度上らないための記憶である。一度も上っていなければ 0 のままなので、下りの最深には使えない。ADR 0004 はシードの桁を切らず、幅が足りなければ欄ごと落とす。ADR 0013 は最深記録をこの決定の外に置いている。

## 決定

記録は、この起動で着いた階の最大である。B1F は 1。着地と階の移動で、いまの階と移動先の深い方まで上げる。上に戻しても減らない。攻撃、一言、歩数の記録は、その値を保ったまま写す。

画面は `*B7F` である。いまの階の右に置く。色は階の数字と同じである。幅が足りないときは、座標、いまの階、シードより先にこの欄を落とす。桁は切らない。ファイルには書かない。

## 強制

値は `Delver.deepest` だけが持つ。更新は `Delver.reaching` だけが行う。文言は `ScreenText.recordLabel` だけが作る。Render は時計を読まない。`HudBrief` と `paint` の引数は 4 つのままである。

ゲートは、開始が 1 であること、下りで増え上りで減らないこと、写しても残ること、80 列で `*B7F` が階のそばにあること、幅 40 でシードの全桁と座標といまの階が残り、長いシードでは記録が先に落ちることをテストする。

## 結果

深く潜って上へ戻っても、HUD に最深が残る。同じシードのフレームは、前の起動に依存しない。幅 40 では、記録が先に落ちることがある。宝箱のミミックは、この決定では特別にしない。

## 却下した選択肢

| 選択肢 | 却下の理由 |
| --- | --- |
| `risen` を表示する | 上りの記憶であり、下りだけでは 0 のままである |
| ファイルや環境に残す | 同じシードのフレームが前の起動に依存する。時計と環境を読んでよいのは実行ファイルだけである |
| HUD に行を足す | 5 行のまま迷路を 19 行に保つ |
| シードや階より後に落とす | 幅 40 でシードの桁といまの階が残らなくなる |
| 記録の桁を途中で切る | 欄は全体で残すか、全体で落とす |
| 文言を Core に置く | 画面の文言は Render が持つ |
| `Delver` や `HudBrief` や `paint` に引数を足す | 引数は 4 つまで。記録は既存の走者が持つ |
| 新しい一言を足す | 記録は欄である。遭遇の一言は既にある |
| ミミックを同じ変更に混ぜる | 一つずつ着地する |
